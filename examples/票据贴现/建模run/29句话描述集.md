## 1. 对象描述类

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 1.1 | 本场景核心业务对象为：票据（本场景仅商业承兑汇票）、持票人（企业）、承兑人（企业）、贴现申请、背书记录，共 5 类 | owl:Class ×5 |
| 1.2a | 票据具有属性：票号（字符串，格式 PJ+12 位数字，唯一）、票面金额（xsd:decimal，>0，币种人民币）、出票日期（xsd:date）、到期日期（xsd:date） | owl:DatatypeProperty ×4 + 格式/取值约束 |
| 1.2b | 承兑人具有属性：统一社会信用代码（字符串，唯一标识）、信用等级（受控枚举：AAA/AA/A，平台内部评级） | owl:DatatypeProperty ×2 + 枚举 |
| 1.2c | 持票人具有属性：统一社会信用代码（字符串，唯一标识）、企业名称 | owl:DatatypeProperty ×2 |
| 1.2d | 贴现申请具有属性：申请编号（字符串，格式 ZX+日期+4 位序号，唯一）、申请日期（xsd:date）、期望贴现金额（xsd:decimal，>0）、申请状态（受控枚举：已提交/审核中/已通过/已拒绝/已划款） | owl:DatatypeProperty ×4 + 枚举 |
| 1.2e | 背书记录具有属性：背书日期（xsd:date）、背书序号（xsd:integer，同一票据背书链内唯一且递增） | owl:DatatypeProperty ×2 |
| 1.3a | 票据具有唯一承兑人：票据→承兑人，N:1，承兑人对票据为必填单值 | owl:ObjectProperty（Functional，domain 票据，range 承兑人） |
| 1.3b | 持票人当前持有票据：票据→持票人，N:1（一张票据同一时刻仅一个当前持票人；一个持票人可持多张票据） | owl:ObjectProperty（Functional，domain 票据，range 持票人） |
| 1.3c | 背书记录连接背书人与被背书人：背书人→被背书人（均为持票人类企业），每次背书生成一条背书记录 | owl:ObjectProperty ×2（domain 背书记录，range 持票人） |
| 1.3d | 背书记录归属于票据：票据→背书记录，1:N，按背书序号构成有序背书链 | owl:ObjectProperty（domain 票据，range 背书记录） |
| 1.3e | 贴现申请针对票据：贴现申请→票据，N:1 | owl:ObjectProperty（domain 贴现申请，range 票据） |
| 1.3f | 贴现申请由持票人发起：贴现申请→持票人，N:1 | owl:ObjectProperty（domain 贴现申请，range 持票人） |

## 2. 分层约束类

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 2.1 | 商业承兑汇票是票据的特化；本场景只处理商业承兑汇票——按最小化原则建模裁量：设「票据」单类并将范围收窄登记于 comment，不建银行承兑汇票分支类（超范围） | rdfs:subClassOf（裁量登记，层级实际为 1 层） |
| 2.2a | 贴现申请的五种状态两两互斥（一个申请同一时刻仅处于一种状态） | owl:AllDisjointClasses（状态类）或枚举+Functional（S3 裁量，登记裁量理由） |
| 2.2b | 承兑人信用等级三档（AAA/AA/A）两两互斥 | 枚举受控值+互斥登记 |
| 2.2c | 可贴现与禁止贴现互斥（规则结论类，R3/R4/R5 冲突可检出前提） | owl:AllDisjointClasses |
| 2.4 | 每张票据必须存在唯一承兑人（必要条件：无承兑人的票据不完整） | owl:Restriction（someValuesFrom）+ Functional |
| 2.5 | 票面金额与期望贴现金额取值 >0；到期日期 > 出票日期 | owl:Restriction + range/facet（S3 裁量：facet 不可表达时降级 SWRL built-in 或 md 登记） |
| 2.6 | 票号对票据唯一（一票据一票号、一票号一票据）；申请编号对贴现申请唯一；统一社会信用代码对承兑人/持票人唯一 | owl:FunctionalProperty + owl:InverseFunctionalProperty |
| 2.7 | 层级上限：类层级 ≤2 层（极简表达；本场景实际 1 层） | 建模裁量登记 |

## 4. 控制规则类

| 编号 | 描述句（若条件 C 满足，则触发结论 R） | 目标构件 |
|---|---|---|
| 4.1-R1 | 若贴现申请的发起人是该申请所针对票据的当前持票人，则该申请为有效申请；若非当前持票人发起，则该申请一律拒绝 | swrl:Imp（发起人=持票人核对；否定语义的表达方式由 S3 裁量并登记） |
| 4.1-R2 | 若贴现申请日期早于票据到期日期、且到期日期与申请日期间隔 ≥15 天，则该申请可受理；否则不予受理 | swrl:Imp + 日期运算（built-in 可用性由 S3 裁量，不可表达则 md 登记+待确认） |
| 4.1-R3 | 若票据的承兑人信用等级为 A 级，则该票据禁止贴现 | swrl:Imp → 禁止贴现类 |
| 4.1-R4 | 若票据的承兑人信用等级为 AAA 级，则该票据可贴现（资料原文「可以随时申请贴现」——与 R2 的 15 天间隔限制存在潜在冲突，见 4.2） | swrl:Imp → 可贴现类 |
| 4.1-R5 | 若票据票面金额 <10 万元，则该票据不进入贴现池（不受理，但登记留痕） | swrl:Imp + 处置档「仅登记」 |
| 4.1-R6 | 若一张票据已存在状态为「审核中」的贴现申请，则同一时间该票据的其他新申请不得进入审核（最多一笔审核中） | 基数约束（SWRL 计数表达受限——S3 裁量：owl:Restriction cardinality 或应用层校验+md 登记） |
| 4.1-R7 | 若票据的背书链连续（每次背书的背书人=上一次背书的被背书人，首手为出票时收款人），则该票据背书有效；背书链断裂的票据不得贴现 | owl:ObjectProperty（Transitive 上游持有关系）+ swrl:Imp（连续性形式化方式 S3 裁量并登记） |
| 4.2a | 规则结论类互斥登记：可贴现 ⊥ 禁止贴现（2.2c）——R3 与 R4 前提互斥（信用等级枚举互斥），无组合同真，非真冲突 | 规则元数据登记 |
| 4.2b | **待确认（潜在真冲突）**：R4「AAA 级可以随时申请贴现」与 R2「间隔 <15 天不予受理」对「AAA 级票据剩余期限 <15 天的申请」结论冲突——优先级资料未给出，须业务裁定（G1/G2 待确认项，不补造） | 规则优先级登记（悬置） |
| 4.3 | 违反处置档：R1 违反→拒绝（拦截）；R2 违反→不予受理（拦截）；R3 违反→禁止贴现（拦截）；R5 违反→不受理但登记留痕（仅登记）；R6 违反→不得进入审核（拦截）；R7 违反→不得贴现（拦截） | 处置档登记（structure-patterns §四） |

## 5. 流程活动类【扩展位：md 结构化描述】

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 5.1 | 贴现流程五步：①持票人提交贴现申请（附票据影像）→②平台核验背书链连续性与票据要素→③组织资金方审核→④审核通过后签订贴现协议→⑤资金方划款+票据权利转移登记 | 步骤清单（md） |
| 5.2 | 各步输入：①票据+持票人身份标识 ②贴现申请+票据背书链 ③核验通过的申请+票据要素 ④审核通过结论 ⑤贴现协议 | IOPE-I（md） |
| 5.3 | 各步输出：①贴现申请单（状态=已提交）②核验结论（通过/断裂退回）③资金方审核结论（通过/拒绝）④贴现协议 ⑤划款凭证+权利转移登记（状态=已划款） | IOPE-O（md） |
| 5.4 | 各步前提：①发起人为当前持票人（R1）②申请已提交③核验通过且满足 R2/R3/R5/R7④资金方审核通过⑤协议已签订 | IOPE-P（md） |
| 5.5 | 各步效果（状态迁移）：①→已提交 ②已提交→审核中 ③审核中→已通过/已拒绝 ④无状态变化（协议留痕）⑤已通过→已划款；状态不允许跳跃或回退 | IOPE-E（md）+状态机封闭 |
| 5.6 | 全程留痕：每环节记录操作人、时间、输入输出状态 | 留痕登记（md） |
| 5.7 | 平台角色边界：平台仅组织核验与撮合，资金方独立决策——输出为「推荐+依据」，不做审批承诺 | 输出契约登记（md） |
