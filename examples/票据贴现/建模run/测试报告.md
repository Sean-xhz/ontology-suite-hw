## 3. 通过率轨迹与根因（首跑 26.7% → 重跑 100%）

### 3.1 首跑失败根因：限制⑩（本 run 第 5 项实测定案）

**现象**：11 条「期望一致」用例全部报 inconsistent；4 条「期望不一致」用例通过但属假阳性叠加（任何断言 billNumber/faceAmount 的个体都会炸）。

**定位过程**（削减实验，未盲改本体/用例）：
1. G5 最小化（Bill+4 数据属性）仍不一致 → 仅 `a :Bill` 一致
2. 逐属性对照：C1（billNumber）/C4（faceAmount）不一致；C2/C3（日期）、C5（enterpriseName）、C6（USCC）一致
3. C1'/C4' 剥离具名 datatype 三元组（25 条）→ 恢复一致

**根因**：Pellet 2.3.1 Jena loader 忽略 facet 类具名 datatype（`owl:onDatatype`+`owl:withRestrictions` 的 xsd:pattern/minExclusive）的 facet 三元组（Unsupported axiom 告警）——**模式层（individuals=0）兼容**；但个体断言字面量值后，Pellet datatype 推理对值空间判空 → range 违反 → **假不一致**。即：限制⑨（枚举 datatype）的姊妹限制，触发条件从「本体形态」变为「本体形态 × 实例断言」组合，L3 模式层验证无法暴露。

**处置**：
- 执行器加 `strip_named_datatypes()`：仅剥离 URIRef 具名 datatype 的声明与引用三元组，**内联匿名 bnode oneOf 保留**（实例层可强制执行，见 §4.2）
- 本体与用例零改动（facet datatype 是合法 OWL 2 形态，HermiT/Protégé 正常消费；缺陷在 Pellet 实例层）
- facet 实例校验职责转 L2 脚本 + 数据管线承接（与 F1/F2/F5 族登记口径一致）
- 限制⑩登记为引擎限制（reasoner-limits），执行器 strip 降级承接，本体零改动

### 3.2 归因分类说明

首跑失败不属于模板三类归因（模型缺陷/用例错误/规则冲突）——登记为**第四类「执行环境限制」**（执行器降级承接，本体与用例零改动）。

## 4. 关键发现（实例层新增实证，超出 S4 模式层认知）

### 4.1 Transitive + SWRL 组合推理实证（示例场景选型目标达成）

票据贴现选型的压测目标（Transitive+SWRL+关系矛盾）全部实证：
- **G3 闭包**：R7 相邻匹配（swrlb:add 序号连续+中转人共享）推出 isUpstreamOf(r1,r2)/(r2,r3)，Transitive 闭包推出 `IndR1.isUpstreamOf = [IndR3, IndR2]`——「首→末可达 ⟺ 全链连续」的机器形态在实例层成立
- **X6 断裂**：中转人不匹配 → 不推出，一致（断裂拦截=应用层，边界清晰）

### 4.2 内联 oneOf 枚举具有 Pellet 实例层强制力（auditor 2.5 预警盲区不成立）

X1（applicationStatus="作废"）/X2（creditRating="BBB"）在**剥离具名 datatype 后仍检出不一致**——内联匿名 oneOf range 在实例层被 Pellet 真实强制执行。这是 v1.2 枚举迁移决策的价值闭环：受控值违反可被推理机检出，不依赖应用层校验。S4 auditor 曾预警「Pellet 可能忽略内联 oneOf」——实测证伪，登记为正向惊喜。

### 4.3 R6 公理由空真恢复实质生效的实证

X3（同票两笔「审核中」申请）检出不一致——maxQualifiedCardinality 1 在实例层真实生效。v1.1 状态下（ApplicationUnderReview≡⊥）此用例将假通过；S4 第 2 轮 auditor 的高价值确认（枚举迁移恢复 R6 效力）获实例级证据。
