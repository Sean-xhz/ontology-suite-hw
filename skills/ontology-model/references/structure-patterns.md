# 结构模式参考（建模方案文档骨架）

> **用途**：S2/S3 阶段产出「建模方案.md」时的结构骨架参考。蒸馏自已完成的业务域本体建模实践（18 实体/17 关系/26 公理/5 场景切片的四层方案文档），**只保留结构方法论，零业务内容**。
> **两级标注**：`[verified]` = 已经多场景实践复核且结构上域无关（证据明细见本 skill `CHANGELOG.md` 实证证据登记）；`[provisional]` = 归纳自单案例、待新场景复核——新场景试跑后应复核并更新标注。
> **配例纪律**：本文档所有示例一律虚构中性（取自票据贴现类通用场景），禁止从任何真实业务方案文档摘抄实例。

## 〇、边界清单（硬规则）

- **可入本文件/skill 资产**：要素模板的字段定义、四层组织法、公理分族框架、切片四元组结构、处置档分类、设计原则的抽象表述
- **禁入**：任何真实项目的实体编号与实体名、真实规则内容与阈值参数、真实机构/人名/字段名、真实场景切片实例、商务参数
- 新场景建模时：本文件提供**表格结构与字段清单**，内容由该场景的 29 句话描述集填充

## 一、四层组织法 [verified]

建模方案文档按四层组织，每层是独立章节、独立要素模板：

```
┌─ 映射与推理层：数据管线映射 / 运行时推理服务 / 数据口径分层 / 接口契约 / 验收机制
├─ 公理层：N 条公理 × 六要素，按族组织（见 §四）
├─ 关系层：N 条关系 × 七要素（见 §三）
└─ 实体层：N 个实体 × 八要素（见 §二）
```

四层与「事实–事理–行动」三层认知架构的映射 [verified]：

| 认知架构 | 四要素原语 | 四层落位 |
|---|---|---|
| 事实层（世界是什么） | 对象+属性 | 实体层 + 关系层的结构性关系 |
| 事实→事理桥 | 关系 | 关系层的推理用途列 + 边属性 |
| 事理层（世界如何运作） | 规则 | 公理层 + 规则库映射 |
| 行动层（如何改变世界） | 行动 | 映射与推理层（交互步骤 + 行动登记 + 状态机） |

配套原则（八条设计原则的抽象形态，每条 = 陈述 + 场景裁量）[verified（结构+条数，三场景复核）]：
1. **消费驱动，反本体博物馆**——每个构件第一天挂消费链路，无消费点不收
2. **场景最小化，小切口进入**——范围够用且可扩展，首期只做「点」
3. **三层分离，变化隔离**——公共层/领域层/实例层，新增实例不重构 schema
4. **关系优先，边带语义**——关系独立成层，方向/时效/版本绑定等语义挂边属性
5. **机器可校验**——公理必须字段级可判定，不可解析即降级
6. **全溯源，不补造**——每条规则带原文摘录+来源，缺失不生成确定性值
7. **LLM 边界：只读不写**——LLM 产候选，人工确认后生效，不产出结论
8. **约束分级，敏感分离**——公理带约束等级（强/弱/提示），敏感属性登记与执行授权分离

## 二、实体八要素模板 [verified]

每个实体按八要素登记，缺一不可（缺失项显式写「无」或「待补」）：

| # | 要素 | 内容要求 |
|---|---|---|
| ① | 定义 | 一句话本质 + 依据标注（准入标准「描述清晰」） |
| ② | 子类与类型分叉 | 子类枚举 + 类型开关（解析 schema 选择依据；共性上提、特异性下沉） |
| ③ | 核心属性表 | 五列：属性标准名/类型取值/约束要点/消费级/硬软分类；明细内联杜绝外链漂移。**机消费契约**：此五列表头为下游 ontology-review/simulate 的解析契约——列名不得改写或调换（下游按关键词认列兼容旧 run，但新 run 必须用契约列名）；单元格内字面竖线（pipe 字符）必须写成反斜杠转义形态（参见各 run 建模方案 pattern 列写法；pattern 正则/枚举值常见），未转义会切裂下游表格解析。偏离契约的 run 需在 manifest 登记 |
| ④ | 唯一标识 | ID 格式 + 命名法 + 别名处理（实体对齐准确性的决定字段） |
| ⑤ | 生命周期 | 创建→更新→停用状态机（含复核门禁 + 变更记录） |
| ⑥ | 数据来源 | 权威源 + 解析通道 + 来源层级（全溯源不补造） |
| ⑦ | 主数据承接 | 三层数据口径定位（主数据层/候选层/过渡数据）+ 对齐策略 |
| ⑧ | 示例实例 | 脱敏 YAML（3-10 行）——可判定性自检样例，**必须虚构或脱敏** |

属性表两个口径列 [verified]：
- **消费级**：MVP（核心链路消费）/ 运营（非 MVP）/ 治理（组织信息）
- **硬软分类**：硬门槛（→准入硬筛）/ 软要求（→评分排序）/ 未分类——分类权威源须是业务方确认的盘点结论，建模文档不得自创

三级对齐策略 [verified]：

| 对齐级别 | 适用 | 失败处理 |
|---|---|---|
| 强标识对齐 | 有唯一权威 ID 的实体 | 视为不同实例 |
| 组合键对齐 | 多字段联合定身份的实体 | 进人工确认队列 |
| 相似度对齐 | 名称模糊匹配（别名归并、外部对手方） | 进人工确认队列，**不自动归并** |

虚构示例（要素①+⑧形态）：实体「票据」——定义：由出票人签发的、承诺到期无条件支付确定金额的有价证券 [依据：场景资料 §1]；示例实例：`{bill_id: B-0001, amount: 500000, currency: CNY, issue_date: 2026-01-05}`（全虚构）。

## 三、关系七要素模板 [verified]

关系从对象属性中独立成层（「关系一等公民」为实践裁量，书方法论四要素中关系本归属对象属性位——泛化到其他域时保留此裁量但允许场景推翻）[verified（两场景复核）]：

| 模板元素 | 含义 |
|---|---|
| 定义 | 一句话业务语义 + 依据标注 |
| 定义域–值域 | 起点实体类 → 终点实体类 |
| 基数 | 1:1 / 1:N / N:M |
| 逆关系 | 指向关系编号或「未建（理由）」 |
| **关系属性（边属性）** | 挂在边本身的属性清单（非实体属性）；无边属性写「无」 |
| 推理用途 | 哪个 Stage / 哪条公理规则 / 哪个查询模板消费 |
| 所属主链路 | 核心业务链 / 数据管线链 / 行动环链 / 多链（注明） |

边属性触发判据 [verified]：方向、时效、版本绑定、契合度等语义**只能挂在边本身**、两端实体无法承载时，必须建边属性（OWL 落地 = reification 或注解属性，S3 生成时由 generator 裁量并登记）。

逆关系全局约定 [verified（三场景复核；复查时点=生产化反向推理需求）]：不为逆关系单设编号（构件基线冻结后编号保留不复用），反向语义由实例层双向引用与查询模板承载（SPARQL 逆路径同构可用）。

虚构示例：关系「背书转让」——定义：持票人将票据权利转让给受让人的行为；定义域–值域：持票人→持票人；基数 N:M；边属性：背书日期、背书序号；推理用途：背书链传递性推理（Transitive）；主链路：核心业务链。

## 四、公理六要素模板与分族组织法

**公理六要素** [verified]（每条公理一行、六列齐备）：

| 要素 | 内容要求 |
|---|---|
| 编号+名称 | 族前缀+序号；名称 ≤6 字动宾式 |
| 自然语言陈述 | 「若条件 C 满足，则结论 R」句式——业务专家可复核 |
| 形式化表达 | IF-THEN / 一阶逻辑式——机器可转译（OWL 公理或 SWRL 规则） |
| 判定依据 | **字段级**——机器判定所需的确切字段/词典/正则 |
| 违反处置 | 处置档之一（见下表） |
| 约束等级 | 强 / 弱 / 提示（判据 = 失误后果的合规刚性与不可逆性） |

**处置档分类** [verified 结构 / provisional 档数]：

| 处置档 | 语义 |
|---|---|
| 拦截入库 | 机器硬拦：违反值/实例/规则不入库或不进消费位 |
| 入待核验清单 | 保留原文形态，人工确认后放行或退回 |
| 依据链标注 | 不拦截，消费位打标随依据链输出（禁裸值/降权） |
| 双保留+裁决单 | 冲突值双方保留+登记裁决单，人工裁定，禁静默覆盖 |
| 冻结告警（合规专用） | 敏感规则违规消费→规则冻结+合规告警，直至合规裁定 |

**七族组织法** [verified（三场景复核）]：按「违反的发现位点 × 约束对象」分族（R 族按「推导语义」独立成族），族间互不重叠。**消费位差异注记**：六族中 F/S 族在 TTL 形式化面重建成立，C/X/P 族主要归属解析管线与行动环工程文档面（形式化面由 F/L/S/R 族承载）——七族框架跨「本体形式化+工程实施」双文档面完整覆盖，单看 TTL 面会有族空位、属正常分布而非不适配：

| 族 | 一句话定位 | 主要消费位点 |
|---|---|---|
| F 格式族 | 取值形态机器可校验的第一道闸 | 数据管线归一+质检位 |
| L 逻辑族 | 字段间/构件间语义自洽与可判定 | 质检+判定前置位 |
| C 治理族 | 反臆造/反静默合并/溯源完备 | 解析纪律+入库门禁位 |
| P 完整性族 | 缺失显式登记、不静默消费 | 入库门禁+待补清单位 |
| X 行动族 | 决策权归人与留痕的技术机制 | 运行时行动环位 |
| S 敏感族 | 敏感规则全链合规控制 | 质检+合规审查双位点 |
| R 推导族 | 「条件⇒结论」推导规则（SWRL 规则/定义类承载形式化） | 判定前置位+消费链路出口 |

**R 推导族说明**：推导型规则与约束型公理语义正交——约束族服务「不可违反断言」（违反→处置档），推导规则是「条件⇒结论」的知识编译（不触发=未判定≠违反，否定方向由应用层拦截并登记）。R 族独立成族而非并入 L 族的理由：发现位点（判定前置位 vs 质检位）与约束对象（结论类 vs 字段/构件关系）均不同。要素模板复用六要素中可复用列（自然语言陈述/形式化表达/判定依据/违反处置〔承载处置档+否定方向归属〕/约束等级），R 族条目在建模方案中独立成节（§4.R，R 前缀编号；示例载体 examples 基准 run 可参照）。

新场景适配规则：**先尝试七族直接套用；不适配（某族为空/需要新族/粒度错位）时按「发现位点×约束对象」逻辑重划，并在建模方案中登记裁量理由**——七族不是标准，分类逻辑才是。

**族外边界** [verified]：「参数×阈值」类经验判断不入公理族，由专家规则库（须署名确认）承载——公理层放机器可判定断言，防「全部强约束→Agent 退化为规则引擎」。

**约束等级分布自检** [verified（两场景复核）]：强监管域基线参考值≈77% 强约束占比（数据质量门禁+合规刚性为主体，两场景精确复现）。新场景若强约束占比显著更高，检查是否把建议类语义误入公理族。

虚构示例（六要素一行）：F 族「背书日期格式」——若背书日期字段存在，则须匹配 ISO 8601 日期格式 ｜ `IF endorse_date(v) THEN v ⊨ YYYY-MM-DD` ｜ 判定依据：字段值×正则 ｜ 违反处置：入待核验清单 ｜ 约束等级：弱。

## 五、场景切片四元组 [verified]

切片 = 最小必要本体的按需加载单元。每个运行场景一个切片，切片登记四元组：

| 切片要素 | 内容 |
|---|---|
| 构件子集 | 本切片激活的实体/关系/公理/规则编号清单（显式列**未启用构件**及理由） |
| 推理链 | 编号步骤：输入→各判定步→输出；每步注明消费的构件 |
| 改造路径 | 新增实例/新增类型时本切片的最小增量动作（应趋近「仅实例化、结构零改动」） |
| 复用关系 | 与其他切片的构件交叠：共享实体/全局口径公理/场景专属关系/公理集交叠（交叠=∅ 则可独立升级；交叠≠∅ 则须版本同步） |

切片的三重身份 [verified]：①按需加载单元（防全量注入的 Token 爆炸与信号稀释）②意图-本体对齐的对象（子意图按颗粒度适配切片）③AI 任务管理单元（一个任务一个切片，目标明确/效果可评估/闭环可控）。

## 六、文档级配套机制 [verified]

- **版本纪律**：schema 新值→词典升级流程→小版本；结构增删→大版本评审
- **数据口径三层**：主数据层（唯一权威源）/ 实例候选层（管线产出，人工复核后生效）/ 过渡数据（非权威源，消费必带陈旧标记）
- **规则库映射**：公理族与运行时规则组（路由/硬筛/治理/专家实例/输出）的交叉映射表——公理是断言，规则组是执行编排，分表登记
- **评审机制**：准入四标准（描述清晰/逻辑正确/内容完备/极简表达）作构件入库门禁；双模型质检四元组（严重级别-问题描述-本体位置-修改建议）；争议人工仲裁

## 七、SWRL 编译形态约束（Pellet 2.3.1 实测） [verified]

R 推导族条目编译为 `swrl:Imp` 时的**形态硬约束**——违反不报语法错，而是推理阶段**结论静默丢失**（L1/L2 均不拦截，只有 S6 用例执行才暴露）。**生成期预防优于验收期返工**（两 run 实证与返工成本见 `CHANGELOG.md` 实证证据登记 B 节）——S3 委托 prompt 已内置同款约束（`assets/prompt-generator.md`「SWRL 编译形态约束」段为编译细节权威），本节登记结构层含义：

| 约束 | 结构层含义（建模方案文档面） |
|---|---|
| **head 单原子化**（限制⑪） | R 族条目「一条规则一个结论」；双结论语义（如「⇒ 结论类 + 拒因引用」）在建模方案中登记为**规则对**（主规则+派生规则），不登记为单条 |
| **body 避免同构**（限制⑫） | 拆分出的规则对须在文档中显式登记**两通道形态**：通道一 body 含定义类原子/head 属性原子；通道二 body 为定义类按等价类展开的字面量原子/head 类原子——两通道联合承载原语义，文档不得只写其一 |
| **body 慎用定义类原子** | 结论类断言优先走字面量 body 通道（最稳）；定义类原子仅在双通道需要句法相异时使用。批量场景存在偶发波动观察项（主规则通道），生产验收标准=**≥2 轮全量复跑零 FAIL** |
| **facet 具名 datatype 剥离**（限制⑩） | 实例级推理执行前剥离具名 datatype 声明（执行器内置 strip）；本体文件不因此改动，facet 校验由 L2 脚本+数据管线承接 |

引擎边界注记：以上为 **Pellet 2.3.1** 实测结论。HermiT 复测定案：**不可对照**——HermiT 在 owlready2 通道拒跑含 builtin 的 SWRL 规则，HermiT 档定位=DL 层交叉验证（equivalentClass/disjoint/一致性，与 Pellet 完全同构），swrl_verified 只能由 Pellet 给出；双通道形态保留为 Pellet 硬要求（对 DL 层无副作用）。限制清单与削减实验矩阵见 `references/reasoner-limits.md`（限制⑨-⑬ + §六矩阵）。

## 八、使用纪律

1. 本文件供 S2（组装建模方案框架）与 S3（generator 生成 TTL 时对齐文档结构）加载，**不替代方法论内核**——冲突时以 `methodology-core.md` 为准（内核与源卡片冲突时回报用户裁定，不径改径行）
2. `[provisional]` 项在新场景 run 结束后必须复核：适配→维持标注待更多案例；不适配→修订本文件并在 `CHANGELOG.md` 登记修订理由
3. 从本文件复制表格骨架到 run 产物时，删除标注与虚构示例，替换为该场景实际内容
