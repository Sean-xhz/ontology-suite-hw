# 敏感纪律硬约束

> **用途**：本 skill 处理真实业务场景（各行业域）时的信息安全红线。S0 阶段必读；对真实业务场景 run 全程生效。
> **背景**：业务资料天然携带商务敏感信息与个人隐私信息；本体建模会将其结构化落盘——纪律先行，防泄露面扩大。

## 一、三类敏感信息与处置

| 类别 | 范围（泛化列举） | 处置规则 |
|---|---|---|
| **商务参数** | 交易对手/合作机构真实名称、定价与费率参数、返佣与分润政策、额度与定价梯度、代偿与兜底等保障安排、合作协议细节 | 不入 skill 资产；场景产物中如实登记时须标注「商务参数-对外脱敏」；对外文档一律脱敏或泛化表述 |
| **个人信息** | 姓名、证件号、手机号、住址、征信报告明细、财税明细、企业敏感经营数据 | 最小化原则：本体实例层不写入真实个人数据；样例/测试数据一律虚构或脱敏（遮盖姓名/证件号/企业名/电话/地址）；采集字段以建模消费必要性为限 |
| **内部决策信息** | 内部裁定过程、推理链、交付质量负面评价、组织内部称谓与人事信息 | 不入对外协作文档（只体现最终结论）；内部工作文档可如实登记并标注 |

## 二、目录与版本控制纪律

1. **真实业务场景 run**：产物目录必须位于**受控目录**（不进版本控制/不进入对外分发通道；git 忽略区惯例见 ontology-model README「环境与目录约定」）——S0 阶段确认目录版本控制状态并登记入 run-manifest
2. **虚构/通用场景 run**（试跑、演示、模板验证）：可用版本控制目录（runs_root 默认位置，见 README 目录约定），前提是数据全虚构且不含任何真实商务参数
3. **skill 资产红线**：本体三 skill 资产目录（ontology-model / ontology-review / ontology-simulate 的 references/assets/scripts）与配套 agent 定义属可分发资产——**永不写入任何真实业务数据**；模板配例一律用虚构中性示例
4. **产物不入 skill 目录**：任何 run 的交付产物禁止写入 skill 资产自身目录（机械防线：agent 铁律+主会话复核）

## 三、本体建模专项纪律

1. **schema 登记 ≠ 执行授权**：敏感属性（如民族/宗教/健康等受保护属性）即使业务上真实存在为准入规则，本体登记时必须加敏感标注+合规审查注记——登记的是知识形态，不构成执行许可
2. **个人信息保护三原则**（采集侧字段入本体时核对）：以建模消费必要性为限／分级授权／不诱导过度收集；仅保留消费相关加工变量，不留存原始报告全文
3. **推荐/决策类输出边界**：涉及审批、定价等决策的本体规则，输出表述保持「推荐+依据链」性质，不承诺审批结果（决策权归属外部机构）
4. **样例文件脱敏**：黄金用例、测试矩阵、演示数据中出现的主体名称一律虚构；从真实资料改编时执行五项遮盖（姓名/证件号/企业名/电话/地址）

## 四、执行时序

- **S0**：确认 run 目录版本控制状态（受控/可分发）；判定场景敏感级（真实业务/虚构通用）；登记入 manifest
- **S1/S2**：萃取与描述句组装阶段即执行个人信息最小化（原始资料中的真实个人数据在进入 29句话前替换为虚构标识）
- **S3-S6**：产物落盘前跑敏感自查（泛化模式内置于 closeout_check，真实机构名/人名词表外置经 `--patterns` 传入，见 `assets/tpl-golden-cases.md` 敏感前置检查）；命中即脱敏后再落盘
- **交付**：manifest 登记敏感自查结果；对外协作版本执行商务参数脱敏
