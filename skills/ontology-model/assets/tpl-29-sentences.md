# 「7+1」29 句话描述集模板

> **用途**：S2 语义原料组装阶段的主产物模板——把业务叙述固化为标准描述句集，作为 S3 生成（ontology-generator）的直接输入契约与 G1 准入评审的评审对象。
> **权威依据**：方法论内核 `references/methodology-core.md` §2（源 KC-20261013-005「7+1」框架 / KC-20261013-006「29 句话」模板）。七类名与原书图 6-1 一致（7 类合计 29 子项，2026-11-10 按原书图核对确认）；本模板子项表为**编译导向重构**——子项按 NL→W3C 构件映射需要扩展重排（对象描述类 2→3 拆分、控制规则类 1→3 扩展，其余五类子项数一致但视角按构件重排），编号为模板自身体系，不硬引原书子项编号。
> **填写纪律**：只写 AI 业务意图范围内的业务（最小化双原则）；每句无修辞冗余、术语与《术语词典》一致；写不出某类句子=该类语义缺失，显式登记「本场景无此类语义」而非跳过。

## 使用说明

1. 复制本文件到 run 目录，命名 `29句话描述集.md`
2. 按 7 类逐节填写；每类先核对「标准句式」，再填描述句
3. 每句右侧登记目标 W3C 构件（供 S3 映射自检与 G1 初审）
4. 第 8 节「目标评估」必填——它是防「本体博物馆」的框架级保险
5. 扩展位三类（流程活动/权限管控/CRUD）在 MVP 中降级为 md 结构化描述，不产出 BPMN2.0/ODRL/SPARQL 形式化文件

## 1. 对象描述类（句式：「X 具有属性 Y，取值范围为 Z」）

绑定构件：RDF/OWL（Class、DataProperty、ObjectProperty）+ SKOS（标签）

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 1.1 | 本场景的核心业务对象有哪些，各自是什么 | owl:Class |
| 1.2 | 每个对象具有哪些属性，取值范围是什么 | owl:DatatypeProperty + range 约束 |
| 1.3 | 对象之间存在哪些关联（谁指向谁、方向、基数） | owl:ObjectProperty + domain/range |

虚构示例：「票据具有属性票面金额，取值范围为正数（xsd:decimal，>0）」「票据具有出票人，取值范围为交易对手类实体」。

## 2. 分层约束类（句式：「所有 A 都是 B」／「A 与 B 不相交」）

绑定构件：OWL（rdfs:subClassOf、owl:equivalentClass、owl:AllDisjointClasses、Restriction）

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 2.1 | 哪些对象是其他对象的特化（分类层级） | rdfs:subClassOf |
| 2.2 | 哪些类互斥（一个实例不能同属两类） | owl:AllDisjointClasses |
| 2.3 | 哪些概念等价（不同称呼指同一事物） | owl:equivalentClass |
| 2.4 | 某类实例必须满足什么必要条件（存在量化） | owl:Restriction（someValuesFrom） |
| 2.5 | 某类实例的属性值受什么值域限制 | owl:Restriction + range |
| 2.6 | 某属性对某类实例是否必填/唯一 | cardinality / FunctionalProperty |
| 2.7 | 层级上限：分类到几层为止（极简表达约束） | 建模裁量登记 |

虚构示例：「所有银行承兑汇票都是票据」「商业承兑汇票与银行承兑汇票不相交」。

## 3. 术语类（句式：「X 又称 Y，首选标签为 Z」）

绑定构件：SKOS（Concept、prefLabel、altLabel、broader、narrower、definition）

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 3.1 | 业务术语的标准名称与定义是什么 | skos:Concept + skos:definition |
| 3.2 | 每个术语有哪些同义词/别名/口语说法 | skos:altLabel（首选词= prefLabel） |
| 3.3 | 术语之间的上下位关系是什么 | skos:broader / skos:narrower |

虚构示例：「贴现又称贴现融资、买断式贴现（口语），首选标签为『贴现』，定义：持票人在票据到期前将票据权利转让给金融机构以获取扣除利息后资金的行为」。

## 4. 控制规则类（句式：「若条件 C 满足，则触发结论 R」）

绑定构件：SWRL（swrl:Imp；量化阈值写入条件）

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 4.1 | 业务判断规则：若什么条件成立，则得出什么结论（含阈值、量化关系——数值必须保留原样） | swrl:Imp（ClassAtom / ObjectPropertyAtom / DatavaluedPropertyAtom） |
| 4.2 | 规则之间有无优先级或互斥关系 | 规则元数据登记 + 结论类 disjoint（冲突可检出的前提） |
| 4.3 | 违反规则的处置动作是什么 | 处置档登记（拦截/待核验/标注/裁决单） |

虚构示例：「若票据剩余期限小于 30 天且承兑人评级为 AA 级以上，则该票据可贴现」「可贴现与禁止贴现不相交」。

**硬提示**：规则冲突要能被机器检出，冲突规则的结论类之间必须有 disjoint 声明——填 4.1 时同步核对 2.2。

## 5. 流程活动类【扩展位】（句式：「步骤 S 的输入/输出/前提/效果」）

绑定构件：BPMN2.0 + OWL-S（IOPE）。**MVP 降级为 md 结构化描述**——按四要素表格登记，不产出形式化文件。

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 5.1 | 业务流程包含哪些步骤，顺序是什么 | 步骤清单（md） |
| 5.2 | 每步的输入是什么 | IOPE-I（md） |
| 5.3 | 每步的输出是什么 | IOPE-O（md） |
| 5.4 | 每步执行的前提条件是什么 | IOPE-P（md） |
| 5.5 | 每步执行后产生的效果（状态变化）是什么 | IOPE-E（md） |

虚构示例：「步骤『贴现申请提交』：输入=票据+持票人身份证明；输出=贴现申请单；前提=票据未到期且背书连续；效果=申请状态从『草稿』变为『待审核』」。

## 6. 权限管控类【扩展位】（句式：「角色 R 可以/须经确认/禁止执行动作 A」）

绑定构件：ODRL（Policy）。**MVP 降级为 md 结构化描述**。

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 6.1 | 哪些角色参与本场景 | 角色清单（md） |
| 6.2 | 每个角色可以自主执行哪些动作 | 自主档（md） |
| 6.3 | 哪些动作必须经人工确认后才可执行 | 确认档（md） |
| 6.4 | 哪些动作被禁止（任何角色不可执行） | 禁止档（md） |

虚构示例：「审核角色可以自主执行『查询票据背书链』；须经确认后执行『贴现放款登记』；任何角色禁止执行『修改已生效票据的票面金额』」。

## 7. CRUD 查询类【扩展位】（句式：查询模板自然语言描述）

绑定构件：SPARQL。**MVP 降级为 md 结构化描述**（登记查询意图+预期返回，S6 黄金用例直接消费本节）。

| 编号 | 描述句 | 目标构件 |
|---|---|---|
| 7.1 | 创建：哪些实体由谁在什么时机创建 | 创建登记表（md） |
| 7.2 | 读取：核心业务问题有哪些（必须能回答的问题清单） | 查询意图表（md） |
| 7.3 | 更新：哪些字段可更新、谁有权更新、更新是否留痕 | 更新登记表（md） |
| 7.4 | 删除：允许物理删除还是仅状态停用 | 删除策略（md） |
| 7.5 | 常用组合查询（跨实体关联问题） | 查询意图表（md） |
| 7.6 | 查询结果的可解释性要求（是否须带依据链） | 输出契约（md） |
| 7.7 | 查询性能与并发要求 | 非功能登记（md） |

虚构示例：「读取：给定票据编号，返回完整背书链及各手持票期间」「组合查询：查询所有剩余期限小于 60 天且可贴现的票据，按票面金额降序」。

## 8. 目标评估类（「+1」，必填）

防模型与 AI 业务目标脱节的框架级保险：

| 编号 | 登记项 |
|---|---|
| 8.1 | 本本体服务的 AI 业务意图（一句话） |
| 8.2 | 消费场景清单：每个构件挂哪条消费链路（无消费点的构件不收） |
| 8.3 | 成功判据：模型上线后用什么业务指标衡量（对应 S6 黄金用例通过率与量化闭环） |
| 8.4 | 明确不做什么（范围边界，防蔓延） |

虚构示例：「8.1 支撑票据贴现智能审核 Agent 的准入判定与依据链输出；8.4 不覆盖票据质押与二级市场交易」。
