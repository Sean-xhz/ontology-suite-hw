# S5 可视化把关 Checklist（专家三步审查）

> **用途**：S5 结构把关阶段的执行清单——业务专家（或 G3 扮演者）按「全局拓扑→局部语义穿透→规则路径回溯」三步审查本体结构，专抓 LLM 常漏的分类不当、属性特征误用、规则前提缺失（方法来源见 `CHANGELOG.md` D 节）。
> **执行前提**：S4 已收敛（机械校验+双模型审计通过）。本 checklist 聚焦结构与逻辑；业务语义正确性由 G1 复核会与 S6 黄金用例承接。
> **工具形态**：有 Protégé/图形环境→导入 ontology.ttl 对照执行；**无图形环境（降级，默认）**→运行 `scripts/report_topology.py` 产出文本拓扑报告，对照本清单逐项执行，并在 run-manifest 登记「S5 降级=文本拓扑替代」。

---

## 第一步：全局拓扑审查（重点：对象与关系）

对照类层级树（report_topology.py 输出「类层级树」节，或 Protégé 本体层级视图）：

- [ ] 层级是否成环（A⊑B⊑…⊑A）——机械层 L2-CYCLE 已查，此处复核语义上「像环」的准循环（如两类互为 broader）
- [ ] 有无孤岛类（无父类、无子类、无任何属性挂载）——每个孤岛类问：消费链路是什么？答不出=博物馆构件，回 S3 删除或补挂
- [ ] 分类是否得当：应为不相交的类是否被并列挂到同一父类下却漏了 disjoint 声明（典型：按不同分类轴混挂——如「按承兑人类型」与「按流通状态」两个轴的类混在一层）
- [ ] 层级深度是否异常（单链 >5 层追问每层的业务区分度；扁平化到 1 层追问是否丢失分类语义）
- [ ] 兄弟类颗粒度是否均衡（同一父类下既有粗粒度又有极细粒度类=分类轴不纯）

## 第二步：局部语义穿透（重点：属性与约束）

抽查 3-5 个核心类（优先消费链路最重的类），对照属性表（report_topology.py「对象属性拓扑表」「数据属性表」节）：

- [ ] 每个属性的 domain/range 与业务语义一致吗（方向有没有反：「票据→出票人」还是「出票人→票据」？基数对不对？）
- [ ] 数值 range 有无防呆（金额>0、日期格式、枚举受控）——负数/异常值能否被形式约束挡住
- [ ] 属性逻辑特征是否符合业务常理——逐项过下方四属性校验单

### 四种 OWL 属性特征校验单

| 特征 | 业务语义问句 | 常见误用（AI 生成高发） | 虚构对照示例 |
|---|---|---|---|
| **FunctionalProperty**（函数属性） | 该属性对一个实例是否**只能有一个值**（多对一唯一）？ | 把「可有多个」的属性误标 Functional，导致 reasoner 把两个合法值推成同一实体 | 「票据的出票人」是 Functional（一票一出票人）；「票据的背书人」不是（多次背书多个背书人） |
| **InverseFunctionalProperty**（反函数属性） | 该属性值能否**唯一反推主体**（值→主语唯一）？ | 把非唯一标识误标 InverseFunctional，导致不同实体被推成同一实体 | 「票据编号」是 InverseFunctional（一号一票）；「票据金额」不是（多票可同额） |
| **TransitiveProperty**（传递属性） | 该关系业务上**真的传递**吗（A→B、B→C 则 A→C）？ | 把非传递关系误标 Transitive，推理出荒谬结论；或漏标导致层级链补全失效 | 「背书转让前手」传递（A 的前手的前手也是 A 的前手）；「出票人」不传递 |
| **inverseOf**（逆属性） | 正向关系存在时逆向**是否应可推**？逆对是否成对声明？ | 只声明单向关系，双向查询失效；或 inverseOf 声明不对称（P inverseOf Q 但 Q 未声明 inverseOf P） | 「持有」与「被持有」互逆；漏声明则「查某持票人的全部票据」推理不出 |

- [ ] Functional 与 Transitive 未同挂一个属性（形式矛盾，L2-PROP-CHAR 已查，语义层复核业务是否真想表达二者之一）
- [ ] 每条特征声明都能答出「业务上为什么」——答不出即删除该特征（宁缺勿滥：特征声明是推理行为，不是装饰）

## 第三步：规则路径回溯（重点：规则与行动）

抽 2-3 条 SWRL 规则（优先控制规则类 4.x 中消费位点最重的），沿 body→head 代入虚构个体人肉走一遍：

- [ ] **前提完备性**：决策规则的逻辑链条是否漏掉关键前置条件（典型缺陷=「感应即动作」——只凭单一信号触发结论，缺环境/阈值/状态核验节点。对照描述集 4.1 原文逐条件核对 body）
- [ ] **结论合理性**：代入边界个体（恰好满足/恰好不满足阈值），head 推出的结论符合业务常识吗
- [ ] **冲突可检出性**：语义互斥的规则对，其结论类之间有 disjoint 声明吗（无 disjoint = reasoner 检不出冲突，L3 盲区）
- [ ] **触发链闭环**：规则推出的新事实能否被下游规则/查询消费（推出即终点=死知识，回查消费链路登记）
- [ ] 扩展位核对：流程（IOPE 四要素）/权限（三档）在 md 结构化描述中登记完整，无形式化构件混入 ttl
