# S4 辩护/修订 Prompt（ontology-generator 第二轮起专用）

> **用途**：S4 质检博弈轮——审计报告产出后，主会话将四元组缺陷清单回传 ontology-generator，要求其逐条辩护或修订（逻辑博弈机制来源见 `CHANGELOG.md` D 节）。
> **消费方式**：全文注入 generator 的辩护轮任务指令；`{{...}}` 占位符由主会话替换。辩护轮复用 prompt-generator.md 的角色设定（语义编译官纪律不变）。

---

## Prompt 正文（以下全文注入）

【任务】

收到独立审计者的审计报告。逐条审查全部四元组问题，每条**二选一**回应：

1. **辩护**——认为审计有误：给出基于 29 句话描述集原文、术语词典或 W3C 规范的逻辑辩护理由，引用具体条目（如「描述集 4.1-规则3 原文为……，本体编译无误」）
2. **修订**——承认缺陷：说明改法，并在修订版本体中落实

**硬纪律**：
- 禁止沉默跳过任何一条——每条四元组必须有辩护或修订记录
- 禁止无依据辩护——辩护理由必须引用输入文件或 W3C 规范条文，「业务上通常如此」不构成依据
- 禁止借修订之机自创知识——修订只针对缺陷条目，不夹带描述集之外的新构件
- 对同一条目不得两轮重复相同辩护理由而不补充新证据（第 3 轮仍僵持→标记升级 G2）

【输入】

1. 上一版本体文件：`{{ontology_vN.ttl 路径}}`
2. 审计报告四元组清单（第 {{N}} 轮）：`{{缺陷清单}}`
3. 29 句话描述集：`{{29句话描述集.md 路径}}`
4. 术语词典：`{{术语词典.md 路径}}`

【输出】

1. **辩护与修订说明**（逐条对应四元组）：

| 审计条目（序号+严重级别） | 回应类型（辩护/修订） | 依据或改法 | 落实情况 |
|---|---|---|---|
| #1 阻断：…… | 修订 | 补 disjoint 声明…… | v2 第 45 行 |
| #2 重要：…… | 辩护 | 描述集 2.4 原文「……」，someValuesFrom 编译正确 | — |

2. **修订后的完整本体**（新版本号 vN+1）——输出完整 Turtle 文件，**不是 diff 片段**；未涉及的构件保持原样，禁止顺手重构
3. 文末「编译缺口登记」节延续更新（若修订暴露新的输入缺口）

【升级规则（写入回应表备注列）】

- 涉及**核心业务规则**的争议（控制规则类 4.x 的语义分歧、disjoint 判定分歧）：无论辩护信心高低，一律标注「建议升级 G2」——核心规则争议不可由模型自裁
- 第 3 轮仍未收敛的条目：全部标注「升级 G2」，由人工仲裁终局

---

## 主会话下发注意事项（不注入 agent）

- 辩护轮产物：修订版 TTL（generator 直接写 run 目录）+ 辩护与修订说明（返回主会话，并入缺陷报告「轮次收敛记录」）
- 主会话收到回应后跑机械校验（validate + check_consistency）再送下一轮审计——机械层回归失败直接打回，不消耗博弈轮次
- 收敛判据：审计裁定「通过」或「修订后通过且零阻断」→ S4 结束；3 轮未收敛 → G2 人工仲裁全量遗留条目
