# A/B 三臂实验协议（ontology-simulate 第二协议）

> **定位**：与 what-if 共享物化内核的第二协议——三臂同题面/同应答契约/同模型，仅注入材料不同，量化「形式化相对自然语言的增量」与「知识注入相对裸模型的增量」。
> **本文件=A/B 协议的唯一迭代入口**（防堆砌纪律）：协议条款修订、新执行纪律、参数调整一律进本文件；SKILL.md 只留三臂定义、AG2 闸门与指针，不叠加条款。子协议版本（应答契约/题库 schema）独立登记于 `CHANGELOG.md`，不随 skill 版本号联动。
> 消费方：ab-responder agent（应答）、ab_score.py（机械判据+盲评聚合）、tpl-ab-questionbank.md（题库契约权威）、tpl-ab-report.md（报告骨架）。

## 三臂定义

- **①本体臂**：注入该题画像物化结果——应答契约 v1.1 起用 `simulate_reason.py --render-md` 业务语言渲染+原始 JSON **双轨注入**（渲染层修复「应答暴露规则 ID/物化记法」的可读性损伤，溯源记法保留在依据括注内）；L1 事实题注入 signature TBox 摘要
- **②描述集臂**：注入 29句话描述集全文
- **③裸臂**：无材料（仅通用指令）

> **应答契约版本**：当前 v1.1=本体臂材料双轨（render-md 渲染层）+三臂统一表述纪律（prompt-ab-responder.md 第 6 条）。v1.1 自登记后新 run 生效，历史 run 不回改——引用历史数字时按该 run 登记的契约版本口径披露（版本史见 `CHANGELOG.md` B 节）。

## 题库编制契约（`assets/tpl-ab-questionbank.md` 为契约权威）

- **出题素材白名单**：建模方案规则表（R 族）/F 族 L 族约束/残留风险登记/黄金用例同构变体——**禁凭空出题**；每题 notes 登记素材来源（行号/编号）
- **编制分工**：主会话构造题目+裁定 gold；可委托 agent 扩展同构变体，但 **gold 由主会话裁定并经用户确认**
- **gold 交叉核验**：与本体臂物化结果对照——冲突登记裁定（gold 错→修 gold；本体错→走入口 (c)），裁定后重新冻结
- **冻结双哈希**：题库 md + questionbank.json 双 sha 登记；任何改动即重冻结+全量重跑三臂

## 执行纪律

1. **题库冻结**：三层（L1 事实/L2 推理/L3 边界；题量建议 10-15，实证基线 12）构造 → 按上述编制契约核验冻结；改动即重新冻结并全量重跑三臂
2. **公平性**：三臂同题面/同应答契约（`assets/prompt-ab-responder.md` 逐字一致，仅注入材料节不同）/同模型；每臂×每题独立会话（防上下文泄漏）；应答官臂别无关
3. **应答落盘**：`<answers>/Q01-arm1.json`（三段式：结论 label 五选一/依据/置信度）
4. **机械判据**（`scripts/ab_score.py score`）：label 匹配/key_points 覆盖/规则引用真实性/幻觉计数 + 盲评表单生成（三臂乱序代名 A/B/C，seed 确定性，映射表 key.json 仅主会话持有）——机械判据只做确定性核对，语义质量交专家盲评（LLM-as-judge 在结构化知识上不可靠）
5. **专家盲评**（建议 2 人=评分者间一致率计算的最低人数；任意异步通道——表单/文档/邮件均可，通道由调用环境自定）：逐题三维度评分（建议默认 1-5 分制：业务正确性/解释质量/依据充分性；维度与量表可调，调整须登记 run-manifest），不露臂别；回收后归一为 scores JSON → `ab_score.py aggregate`（含评分者间一致率；表单格式不限，aggregate 只吃 scores JSON 契约）
6. **AG2 终审（人工闸门·停等）**：`assets/tpl-ab-report.md` 六节报告（机械判据+盲评聚合+对照分析+**公平性披露**+**样本量限制与结论边界**为强制节）呈用户终审；未过 AG2 的数字不入任何对外材料；禁止「本体无用/万能」式泛化
