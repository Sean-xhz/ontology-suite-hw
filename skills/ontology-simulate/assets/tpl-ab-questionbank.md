# A/B 题库模板（实验契约）

> 三臂实验的题目载体。题库一经**冻结+哈希登记**即不得改动——任何改动（含措辞微调）须重新哈希并**全量重跑三臂**（防题目版本混杂污染对照）。

## 一、结构

题库双载体（同构，md 人读 / json 机读）：

- `题库.md`：冻结文档（元信息 + 逐题卡片），hash 登记入 run-manifest
- `questionbank.json`：ab_score.py 机械消费，schema 如下

```json
{
  "meta": {
    "schema_version": "1.0",
    "scenario": "票据贴现（虚构）",
    "ontology_ttl": "<相对路径>",
    "ontology_sha": "<TTL sha 前 12 位——题目与本体版本绑定>",
    "frozen_date": "YYYY-MM-DD",
    "frozen_sha": "<题库 md 文件 sha 前 12 位>",
    "layers": {"L1": "基础事实", "L2": "规则推理", "L3": "边界异常"}
  },
  "questions": [
    {
      "id": "Q01",
      "layer": "L1",
      "kind": "fact",
      "scenario": "虚构业务情境描述（L1 可为纯知识问句）",
      "question": "题面（三臂共用，逐字一致）",
      "gold": {
        "label": "yes|no|undetermined|conflict|fact",
        "rule_refs": ["R1"],
        "key_points": ["要点短语 1", "要点短语 2"]
      },
      "arm1_material": "本体臂注入材料说明（L2/L3=该题画像物化结果文件；L1=signature TBox 摘要）",
      "notes": "出题依据（黄金用例/建模方案行号）与判分口径备注"
    }
  ]
}
```

## 二、三层设计纪律

| 层 | 占比 | 考什么 | 判定形态 |
|---|---|---|---|
| L1 基础事实 | ~1/3 | 本体/描述集中的事实性知识（受控值、阈值、状态机、约束） | `kind: fact`——key_points 覆盖率 |
| L2 规则推理 | ~5/12+ | 给画像推结论（单规则/规则组合正反向） | label + rule_refs 真实性 |
| L3 边界异常 | ~1/4 | 阈值边界、开放世界未判定、规则冲突、数据违例 | label（undetermined/conflict 为关键区分度） |

> 三层占比与总题量（建议 10-15，实证基线 12）为**建议值**，按载体规模调整须登记 run-manifest；历史 run 口径不回改。

- **编制分工**：主会话构造题目+裁定 gold；可委托 agent 扩展同构变体，但 **gold 由主会话裁定并经用户确认**
- **出题素材白名单**：建模方案规则表（R 族）/F 族 L 族约束/残留风险登记/黄金用例同构变体——**禁凭空出题**
- **画像全新虚构**：L2/L3 题面画像不得复用黄金用例个体名/数值组合（防本体臂背答案；同构变体允许——考推理不考记忆）
- **gold 必须可溯源**：每题 notes 登记出题依据（建模方案规则行/黄金用例编号/残留风险编号）；gold 本身经本体侧核验（L2/L3 应有对应物化结果或 Pellet 判定支撑）
- **undetermined 是合法答案**：开放世界语义下「未推出≠否定」——L3 须含至少 1 题考此区分（裸臂最易过度断言处）
- **conflict 是合法答案**：已登记未裁决的规则组合（如 R4∧R5）考「识别冲突+交人工裁决」而非强行给结论

## 三、三臂材料绑定（公平性契约）

| 臂 | 注入材料 | 材料版本绑定 |
|---|---|---|
| ①本体臂 | L2/L3：该题画像的物化结果（推断三元组+规则归因+一致性）；L1：signature TBox 摘要（类/属性/受控值/规则面） | sim-result.json 逐题落盘，ontology_sha 一致 |
| ②描述集臂 | 29句话描述集.md 全文 | 文件 sha 登记 |
| ③裸臂 | 无（仅通用指令） | — |

三臂**同题面、同输出契约、同模型、独立会话**；应答标注臂别哈希，盲评页不露臂别（A/B/C 代号+乱序，映射表仅主会话持有）。

## 四、冻结流程

1. 题目构造完成 → `shasum 题库.md questionbank.json` 前 12 位登记 run-manifest
2. L2/L3 逐题跑本体臂材料（compiler→check→simulate 管线）→ 材料文件与 gold 交叉核验（物化结论与 gold label 不一致 → 登记裁定：gold 错→修 gold；本体错→走入口 (c)；裁定后**重新冻结**）
3. 冻结后执行三臂；执行期间发现题目缺陷 → 该题作废登记（不修题重用），有效题数如实入报告
